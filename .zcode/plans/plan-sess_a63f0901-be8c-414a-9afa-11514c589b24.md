# Provider-Based AI Generation Integration for PeraByte Studio (approved)

Replace the hardcoded Pollinations render path with a layered provider architecture (controllers in `app/api`, services in `lib/services`, provider adapters in `lib/providers`, repositories in `lib/repositories`, domain types in `lib/domain`, config in `lib/config`, logging in `lib/logging`):

- **Model selection** from the prompt window (PillSelect) for image, video, story, and character generation; catalog: `grok-imagine-image-2.0` / `grok-imagine-image` / `grok-imagine-image-quality` (image), `grok-imagine-video-1.5` / `grok-imagine-video` (video) via apikey.fan (`/v1/images/generations`, async `/v1/videos/generations` + polling), Pollinations Flux kept as keyless free fallback so nothing breaks before the API key arrives.
- **Uncensored Mode**: Settings dialog toggle (default disabled) — the sole gate (no env override); unlocks Character Studio Uncensored mode + NSFW image/video (`safe:false` in request body).
- **Production logging**: zero-dep structured leveled logger with child scopes + API-key redaction, instrumented across API routes, provider HTTP calls, and generation milestones.
- **Media repository**: content-addressed disk cache (`.media-cache/`) served via `/api/media?f=`; b64 images and downloaded mp4s stored server-side; Pollinations URLs keep the existing proxy path.
- **API key** later via `.env.local` (`APIKEY_FAN_API_KEY`), `.env.example` committed, key never shipped to client.
- **Tests**: vitest unit tests for env parsing, request mapping, catalog defaults, settings repository; full verification with typecheck, build, and existing Playwright scripts.
